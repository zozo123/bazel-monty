Bazel 9.1.1 / rules_rust / Remote Cache

Monty, rebuilt as a Bazel remote build.

Monty is a minimal Python interpreter written in Rust, from the Pydantic team. This demo Bazelizes a pinned upstream archive with a small patch overlay — no fork — and takes it from a local build to a measured remote cache; provider cache and remote execution (RBE) are scripted but not yet measured. Every number below is committed as JSON, with the scripts to reproduce it. Built by Yossi Eliaz at Incredibuild, July 2026.

Measured, not estimated

Two fresh Bazel output bases against one bazel-remote instance in Docker. The seed run populates the cache; the reader run consumes it with uploads disabled. No local action cache involved. To be precise about what is measured: this compares a cold full build (with cache upload) to a fully cached rerun of the same targets — both with --remote_download_toplevel.

121.135s Cold seed run — build + test, 756 processes, 0 remote cache hits.
15.706s Reader run — same targets, fresh output base, uploads disabled.
432 / 432 Every executable action on the reader run came from the remote cache. The other 325 processes are Bazel-internal and never cacheable.

Bazel 9.1.1, Crabbox 0.36.0 (openclaw/crabbox), Monty pinned at 4bcbcf5. Islo is Incredibuild's cloud sandbox service; this demo is an Incredibuild project. Process counts are as printed by Bazel's process summary, which does not sum exactly. Full summary in docs/metrics/e2e-results.json.
